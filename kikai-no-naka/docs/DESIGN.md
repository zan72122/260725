# 設計メモ

「きかいのなか」の、考えたことと作りかたの記録。

---

## 1. 何をつくったのか

4歳児が、**因果のつながり**を手で確かめるための道具です。
遊びの中心はひとつだけ。

> **さわる → 何かが動く → べつの何かが変わる → それが目に見える**

この鎖を、切れ目なく見せることに全部を賭けています。
そのために避けたものが 3 つあります。

- **離散的な状態**（オン／オフだけの表現）。すべての量を実数で持ち、なめらかに変える。
- **文字での説明**。4歳児は読みません。動きと色と音で伝えます。
- **失敗**。壊れる操作、間違える操作を 1 つも置いていません。

## 2. 「すけすけ」の設計

外装を消して中を見せる方法はいくつもありますが、
**トグルではなくスライダー**にしたのは、途中の状態こそが面白いからです。
半分だけ溶けた機械は、「外側の顔」と「中の骨」が同時に見えます。

### 波は機械ぜんたいで 1 つ

最初の実装では、部品ごとのローカル座標でディゾルブを判定していました。
すると小さな部品（縁どりやリブ）が一斉にパッと消え、大きな部品だけが
グラデーションで溶けるという、ちぐはぐな見え方になりました。

いまはワールド座標を使い、**機械ぜんたいを 1 つの波が通り抜ける**ようにしています
（`js/lib/xray.js` の `setShellDissolve()`）。
波は「手前の上」から始まり、奥・下へ抜けます。こうするとスライダーを少し
動かしただけで前板が消え、すぐに歯車が顔を出します。

### 途中が「ミルク状」に濁らないようにする

半透明を何枚も重ねると、たちまち白く濁ります。対策は 3 つ。

1. **ディゾルブの境界を細くする**（`smoothstep(front ± 0.11)`）。
   中途半端な半透明の領域そのものを狭くする。
2. **透明度カーブを寝かせる**（`pow(ghost, 0.55)`）。
   少し溶け始めた時点で、しっかり透けるようにする。
3. **重なる層を減らす**。たとえばライトの正面パネルは、当初「板」でしたが、
   歯車の前に 1 枚よけいな層ができるため「枠」に作り替えました。

### premultipliedAlpha を使う理由

透けたガラスの上でリムをしっかり光らせたいのに、通常のアルファ合成では
alpha が小さいほどリムも暗くなってしまいます。
シェル用マテリアルは `premultipliedAlpha = true` にして、
`rgb = base * alpha + 加算光` を自前で書き出しています。

もともと半透明な素材（ガラス・水）が混ざっても壊れないよう、
`makeShellMaterial()` は元の `transparent` を記憶し、
すけすけ 0 のときも半透明のままに保ちます。

## 3. 描写まわり

### 外部アセットをゼロにする

読み込み時間はそのまま「あきらめる確率」です。
3D モデルもテクスチャも HDR も使わず、全部その場で作ります。

| 見せたいもの | つくりかた |
| --- | --- |
| 歯車 | 本物のインボリュート曲線（圧力角 20°）から歯形を計算し、歯元にフィレットを入れて押し出し、面取り（ベベル）で稜線に光を乗せる |
| 円筒系の部品 | すべて断面プロファイルの回転体。角には必ず C 面を入れる（C 面のない円柱は「模型」に見える） |
| 金属のヘアライン | Canvas 2D で異方性ノイズを描き、ラフネスマップとノーマルマップにする |
| 木目・パン・基板 | 同じく Canvas 2D。値ノイズ + fBm |
| 金属の映り込み | ソフトボックスを 6 枚並べた小さなシーンを `PMREMGenerator.fromScene()` で畳み込む |
| 音 | WebAudio のオシレータとノイズのみ |

### 金属が真っ黒にならないようにする

PBR の金属は、**環境に何もなければ何も映しません。**
カメラの側（＝金属の正面が映す方向）に光源がないと、
真鍮の歯車がただの黒い板になります。

環境シーンには、キー／フィル／リムに加えて
**カメラの後ろに大きな面光源**を置いています。これがないと成立しません。

それでも真正面を向いた小さな金属板（時計のねじまきなど）は
見る角度で暗く沈むので、そういう部品は
`coated`（metalness を落とした粉体塗装）に切り替えています。

### トーンマッピングは ACES ではなく Neutral

最初は ACES Filmic を使っていましたが、
4歳児向けの明るい色（ミント・トマト・バター）がことごとく寝てしまいました。
Khronos PBR Neutral（`THREE.NeutralToneMapping`）に変えたところ、
ハイライトを守りながら彩度が残るようになりました。

### ポストプロセス

```
RenderPass（HDR リニア）
  → UnrealBloomPass（しきい値 ≈ 1.0：本当に光っているものだけ）
  → OutputPass（トーンマップ + sRGB）
  → FXAA（MSAA が使えないとき）
  → GradePass（周辺減光・わずかな色収差・粒子・色かぶり）
```

ブルームのしきい値を 1.0 前後に置くのが肝心です。
下げると白い外装まで滲み、画面全体が霧のようになります。
電球・電熱線・コイルは `emissiveIntensity` を 5〜7 まで上げて、
「そこだけが本当に光っている」状態を作ります。

### 屈折（transmission）を使わない判断

`MeshPhysicalMaterial.transmission` は美しいのですが、

- 屈折するもの同士は重ねて見えない（水槽のガラスの向こうの水が消える）
- モバイル GPU では専用のレンダーターゲットぶん重い

という理由で、ガラスと水は素直なアルファ合成にしています。
縁のハイライト（`clearcoat` + 高い `envMapIntensity`）でガラスらしさを稼ぎます。

## 4. 指の入力

### どの角度からでも回せる

回転ハンドルの実装は、掴んだ点の**接線を画面に投影**し、
指の移動をそこへ射影して角度に変えています（`js/core/input.js` の `_updateRotate`）。

```
接触点 → 軸に垂直な半径ベクトル r
接線 t = 軸 × r
画面上での t の向きに、指の移動量を射影 → 弧長
角度 = 弧長 / 画面上の半径（下限 26px）
```

平面への交差判定でも実装できますが、軸が視線と直交すると（＝円が真横から
見えると）破綻します。接線への射影なら、どの角度からでも自然に回せます。

接触点は毎フレーム部品と一緒に回るので、指で円を描くとそのまま回りつづけます。

### 指を何本使ってもいい

ポインタごとに独立してハンドルを掴めます。
片手で歯車を押さえながら、もう片方でハンドルを回す — これができることが、
「つながっている」を伝えるいちばんの近道です。

空いているところを触った指はカメラ操作に回り、2 本になるとピンチになります。

### 当たり判定は見た目より大きく

小さな部品には、`visible = false` の当たり判定用メッシュを添えています。
three.js のレイキャストは `visible` を見ないので、
描画コストゼロのまま、指の太さに合った的を用意できます。

## 5. 画面のレイアウト

縦画面と横画面で、UI の置き場所が変わります。

- **縦**: 上にメーター、下にすけすけスライダーと機械カード
- **横**: 左に機械カードの縦レール、右にすけすけスライダー（縦向き）

3D 側は、UI に隠れていない矩形を DOM の実測値から求め、
`camera.setViewOffset()` でフラスタムをずらして、その矩形の中央に機械を収めます
（`js/core/camera.js` の `frame()`）。
セーフエリアやフォントサイズが違っても、機械がボタンに隠れません。

## 6. 品質の自動調整

初期ティアは端末情報（メモリ・コア数・DPR・iOS かどうか）から推定し、
そのあと実測 FPS で上下させます（`js/core/quality.js`）。

- 落とすときは素早く（2 秒連続で 40fps 未満）
- 上げるときは慎重に（8 秒連続で 57fps 以上、かつ一度も落としていない端末だけ）

ティアが変わると、影の解像度・MSAA・ブルーム・粒の数・テクスチャ解像度が
まとめて切り替わります。

## 7. 音

すべて合成です。連続音（`Voice`）は機械の状態にそのまま追従するので、
「速く回すと音が高くなる」が耳からも分かります。

- 歯車のうなり: ピンクノイズ + バンドパス（中心周波数 ∝ 回転数）
- モーター: のこぎり波 2 本をデチューンして、うなりを出す
- 時計のチクタク: 三角波の短い下降 + 高域ノイズ
- オルゴール: 自由端の棒の倍音比 **1 : 6.27 : 17.55** を重ね、上の倍音ほど速く減衰させる
- ポップアップ: 三角波にビブラートをかけて周波数を落とす「ボヨン」

部品の名前は `speechSynthesis`（ja-JP）で読み上げます。
使えない端末では黙って諦めます。

## 8. あとから足した 6 台で分かったこと

最初の 6 台（ライト／せんぷうき／とけい／オルゴール／みずポンプ／トースター）は、
どれも「動力 → 変換 → 結果」の一本道でした。
あとから足した 6 台では、意識的にちがう性質を選んでいます。

| 機械 | 新しく持ちこんだ考え方 |
| --- | --- |
| えんぴつけずり | **削れて無くなる**。状態が戻らない（新しいえんぴつに替えると戻る） |
| ミシン | **タイミング**。上と下が決まった位相で噛み合わないと成立しない |
| はかり | **行きすぎて戻る**。バネ・質量・減衰の 2 次系そのものが遊びになる |
| エレベーター | **つりあい**。おもりのおかげで軽い、という体験 |
| かぎ | **かたちが情報である**。ギザギザの深さが、そのまま鍵になっている |
| ガチャ | **たくさんのものが押し合う**。26 個の球の位置ベース物理 |

技術的にいちばん手を入れたのは、内歯車（リングギヤ）の生成です。
外歯車の輪郭をピッチ円で内外反転（r → 2·pitchR − r）すると、
そのまま内歯の形になります。これを円板の穴として押し出すだけで、
遊星がころがる相手ができました（`js/lib/geometry.js` の `ringGearGeometry`）。

もうひとつは、機械を続けて切り替えたときの後始末です。
切り替え演出（0.42 秒）の途中でさらに切り替えると、
前の機械の破棄予約が上書きされて取りこぼされていました。
4歳児はカードを連打します。破棄待ちを配列にして、まとめて捨てるようにしています。

## 9. 意図的にやらなかったこと

- **点数・時間制限・達成度**。おもちゃに勝ち負けは要りません。
- **チュートリアルの強制**。案内マークは邪魔にならない程度に出て、触れば消えます。
- **見た目だけの機構**。12 台ぜんぶ、実物と同じ理屈で動かしています。
  えんぴつけずりの遊星比、ミシンの「上軸1回転＝かま2回転」、
  かぎのピンの長さと切りこみの深さの対応まで、数字で合わせてあります。
- **リアルすぎる配色**。実物の灰色より、少し彩度の高いおもちゃの色を選んでいます。
